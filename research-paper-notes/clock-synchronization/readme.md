This repository contains notes and research materials on improving clock synchronization methods. The focus is on exploring how AI/ML can improve clock synchronization. 

The starting point is the paper "Exploiting a Natural Network Effect for Scalable, Fine-grained Clock Synchronization" [nsdi18-geng](https://www.usenix.org/system/files/conference/nsdi18/nsdi18-geng.pdf)

***Below are few other cited papers: which either refer to clock synchronization or use clock synchronization in their study, but not related to us. Documented to refer back in future.***

1. [Fundamental Limits on Synchronizing Clocks Over Networks (Freris, 2011)](https://ieeexplore.ieee.org/document/5605654) - An old paper which outlines the limilations to clock synchronization over networks. It tells what is feasible and what is not feasible w.r.t to clock synchronization. However, they did not propose a new clock synchronization algos.
2. [Non-Hierarchical Clock Synchronization for Wireless Sensor Networks (Brown, 2012)](https://arxiv.org/pdf/1212.1216) - Non-hierarchical, distributed algorithm for clock synchronization that operates at the physical/MAC layers through pairwise bidirectional messaging between nodes. Not related to our study.
3. [DETER: Deterministic TCP Replay for Performance Diagnosis (Li, 2019)](https://www.usenix.org/system/files/nsdi19-li-yuliang.pdf) - A tool to replay TCP - used to trace, troubleshoot and diagnose TCP performance problems.
4. [Bandwidth-efficient Microburst Measurement in Large-scale Datacenter Networks (Gao, 2022)](https://conferences.sigcomm.org/events/apnet2022/papers/Bandwidth-efficient%20Microburst%20Measurement%20in%20Large-scale%20Datacenter%20Networks.pdf) - A bandwidth efficient system for measuring and identifying microbursts. Not related to our study. 
5. [Threshold-Based Routing-Topology Co-Design for Optical Data Center (Cao, 2023)](https://ieeexplore.ieee.org/ielx7/90/4359146/10102400.pdf) - Talks about physical optical circuit switches. Unrelated to our study. 
6. [TROD: Evolving From Electrical Data Center to Optical Data Center (Coa, 2021)](https://ieeexplore.ieee.org/document/9651977) -  Talks about electrical switches. Unrelated to our study. 
7. [Receiver-Driven RDMA Congestion Control by Differentiating Congestion Types in Datacenter Networks (Zhang, 2021)](https://ieeexplore.ieee.org/document/9651938) - New congestion control mechanism for RDMA (Remote Direct Memory Access) in data center networks which relies on high precision clock synchronization throughout the datacenter network
8. [RCC: Enabling Receiver-Driven RDMA Congestion Control With Congestion Divide-and-Conquer in Datacenter Networks (Zhang, 2023)](https://ieeexplore.ieee.org/document/9819970) - New congestion control mechanism for RDMA (Remote Direct Memory Access) in data center networks which relies on high precision clock synchronization throughout the datacenter network.
9. [Towards “Zero-buffer” Datacenter Networks (Wang, 2021)](https://arxiv.org/pdf/2109.13065) - Introduces a new data center network (DCN) architecture that enables the use of extremely simple zero-buffer switches. Unrelated to our study. 
10. [Shoal: A Network Architecture for Disaggregated Racks (Shrivastav, 2017)](https://www.usenix.org/system/files/nsdi19-shrivastav.pdf) - About rack architectures in data centers, unrelated to our study.
11. [Partitioned Paxos via the Network Data Plane (Dang, 2019)](https://arxiv.org/pdf/1901.08806) - Partitioned Paxos, a novel approach to network-accelerated consensus. unrelated to our study.
12. [When Should The Network Be The Computer? (Ports, 2019)](https://drkp.net/papers/innetwork-hotos19.pdf) - About in-network processing and computation, unrelated to our study.
13. [Accelerating the Performance of Data Analytics using Network-centric Processing (Boughzala, 2021)](https://dl.acm.org/doi/pdf/10.1145/3465480.3468162) - Says that in-network real time data analytics will improve performance of current systems because of the programmable switches invented, unrelated to our study. 
14. [P4Pi: P4 on Raspberry Pi for Networking Education (Laki, 2021)](https://www.cs.yale.edu/homes/soule/pubs/ccr2021.pdf) - Just a language for network education. unrelated to our study.
15. [P4xos: Consensus as a Network Service (Dang, 2020)](https://www.cs.yale.edu/homes/soule/pubs/ton2020.pdf) - programmable networking hardware for consensus protocols like Paxos. Unrelated to our study. 
16. [Harmonia: Near-Linear Scalability for Replicated Storage with In-Network Conflict Detection (Zhu, 2019)](https://arxiv.org/pdf/1904.08964) - a replicated storage architecture that leverages programmable switches to achieve near-linear scalability for read operations without sacrificing consistency guarantees like linearizability. unrelated to our study.
17. [Infinite Resources for Optimistic Concurrency Control (Jepsen, 2018)](https://dl.acm.org/doi/pdf/10.1145/3229591.3229597)- NOCC moves transaction processing logic into the network, using a custom packet header and programmable switches to identify and abort doomed transactions as early as possible.
18. [NetChain: Scale-Free Sub-RTT Coordination](https://www.usenix.org/conference/nsdi18/presentation/jin) - NetChain is a new approach that offloads coordination service functionality to programmable network switches, allowing queries to be processed entirely in the network data plane.
19. [NetLock: Fast, Centralized Lock Management Using Programmable Switches](https://dl.acm.org/doi/pdf/10.1145/3387514.3405857) - Same as above, related to programmable network switches but not our area of interest. 
20. [Precise Time-synchronization in the Data-Plane using Programmable Switching ASICs (Kannan, 2019)](https://praveingk.github.io/papers/DPTP_SOSR19.pdf) - does not utilize any machine learning (ML) models. The focus of the paper is on the development and implementation of the Data Plane Time Protocol (DPTP), which leverages the capabilities of programmable switching ASICs to achieve high-precision time synchronization in network data planes. The methodology involves direct packet timestamping and clock drift correction within the network infrastructure.
21. [To Sync or Not to Sync: Why Asynchronous Traffic Control Is Good Enough for Your Data Center (Sviridov, 2018)](https://ieeexplore.ieee.org/document/8647692) -  The focus is on the structural and operational aspects of asynchronous traffic control rather than on leveraging ML techniques.
22. [Awakening Power of Physical Layer: High Precision Time Synchronization for Industrial Ethernet (Qian, 2017)](https://ieeexplore.ieee.org/document/8277288) - Industrial Time Protocol (ITP) deployed in physical layer leverages the InterFrame Gap (IFG) guarantees 16N-nanosecond accuracy for N-hop network. It is related to time synchronization, but does not utilize ML/AI. 
23. [Towards a Programmable Dataplane (Wang, 2017)](https://ecommons.cornell.edu/items/600ffdc4-bcad-4372-8ef9-993d45c0d3fa) - Clock synchronizaton through programmable network dataplane -  a decentralized clock synchronization protocol that provides bounded precision where no two clocks differ by more than tens of nanoseconds. It has clock synchronization, but does not utilize ML/AI. 
24. [PTPmesh: Data Center Network Latency Measurements Using PTP (Popescu, 2017)](https://api.repository.cam.ac.uk/server/api/core/bitstreams/299cd14d-560e-4f5b-9da0-c51f52299c50/content) - A study on Precision Time Protocol statistics (one-way delay, master-to-slave delay, slave-tomaster and clock offset) can be used to measure network latency and detect packet loss. Not related to clock synchronization. 
25. [High-resolution measurement of data center microbursts (Zhang, 2017)](https://dl.acm.org/doi/pdf/10.1145/3131365.3131375) - characterizing the fine-grained, microsecond-scale traffic behaviors and network events in large, high-speed production data center networks. Unrelated to our study. 
26. [Globally Synchronized Time via Datacenter Networks (Shrivastav, 2019)](https://ieeexplore.ieee.org/document/8734740) - DTP protocol that achieves extremely precise nanosecond-level clock synchronization across datacenter networks by operating directly at the physical layer, with zero network overhead. Although the study is regarding clock synchronization, it involves hardware but not AI/ML.
27. [A survey on high-precision time synchronization techniques for optical datacenter networks and a zero-overhead microsecond-accuracy solution (Ahmed, 2018)](https://link.springer.com/article/10.1007/s11107-018-0773-9) -  microsecond-level time synchronization across servers and switches in a packet-switched optical datacenter network. using the Precision Time Protocol (PTP) to synchronize server clocks with a central controller clock. Unrelated to our study. 
28. [Fast General Distributed Transactions with Opacity (Shamis, 2019)](https://www.microsoft.com/en-us/research/uploads/prod/2019/01/mod057.pdf) - FaRMv2 is a distributed transactional system which uses timestamp ordering based on real time with clocks synchronized to within tens of microseconds; a protocol to ensure correctness across clock master failures; and a transactional protocol that uses onesided RDMA reads and writes instead of two-sided messages. It is not related to our study.
29. [Breaking the Transience-Equilibrium Nexus: A New Approach to Datacenter Packet Transport (Liu, 2021)](https://www.usenix.org/system/files/nsdi21-liu.pdf) - On-Ramp (OR) can be coupled with any datacenter congestion control protocol to improve its performance during transients. HUYGEN is used to measure path congestion. It is not related to our study.
30. [1Pipe: scalable total order communication in data center networks (Li, 2021)](https://01.me/files/1Pipe/1pipe-sigcomm21.pdf) - 1pipe delivers messages in sender’s clock time order with restricted failure atomicity. 1Pipe achieves scalability and efficiency  by utilizing programmable data center networks to separate aggregating order information from forwarding data packets. It does not synchronize clocks, but I see that this can be used for logs total order. 
31. [Scalable, near-zero loss disaster recovery for distributed data stores (Alquraan, 2020)](https://www.vldb.org/pvldb/vol13/p1429-alquraan.pdf) - Disaster Recovery (DR) system. Reference to huygens was added only to describe the clock synchronization problem, but neither clock synchronization nor AI/ML related study are in this paper, hence it is not related to us.
32. Design of a high-precision clock distribution and synchronization system https://www.sciencedirect.com/science/article/abs/pii/S0168900224001244 - Clock synchronization specific to CSR External Target Experiment (CEE)(a nuclear physics experiment). It uses a special protocol to synchronize timestamps across all readout electronic nodes achieving low jitter over the distributed network following a master-slave structure.
